# План сохранения и восстановления

Статус: план; создание резервной копии и её восстановление не подтверждены.

## Что сохранять отдельно
1. Полная независимая копия Git-репозитория и история, включая выбранные ветки и теги; зафиксировать коммит 752c8359eb9ce68fbed4c10cf1ffed2db546dd3c как исходную точку.
2. Исходные изображения, подписанный исходный документ и другие материалы, не обязательно присутствующие в Git; каталогизировать происхождение и права.
3. Данные localStorage по каждому устройству и браузеру после оценки содержимого и согласия владельцев; экспорт только в защищённое место.
4. При появлении сервера: проверенные бэкапы базы, файлов, схемы, миграций и конфигурации; сведения об аккаунтах сервисов и восстановлении доступа отдельно от секретов.
5. Параметры домена, GitHub Pages, среды развёртывания и перечень интеграций. Секреты хранить в предназначенном для этого защищённом хранилище.

## Процедура
Назначить ответственного; определить частоту, срок хранения, допустимую потерю данных RPO и время восстановления RTO; зашифровать копии с личными данными; разместить хотя бы одну независимую копию. Проверить читаемость, права доступа и контрольные суммы.

Восстановление сначала выполнять в изолированную тестовую среду: развернуть код и зависимости, восстановить данные, сверить число и выборочные записи, проверить вход и права, зафиксировать затраченное время. Публикацию восстановленной версии выполнять только по отдельному регламенту.

Нельзя считать снимок Git бэкапом localStorage или внешней базы. Не загружать дампы, токены и приватные жалобы в публичный репозиторий.
